# Material Entry module

The **📥 Material Entry** tab records material that enters the factory (goods received).
Issue to Production, Stock and Reports are shown in its sidebar as "soon" and slot into the same module later.

## Files

| File | What it does |
|---|---|
| `materials.js` | The material list (name, default unit, badge colour) and the unit suggestions |
| `entryRepository.js` | Data layer: the only file that talks to the server |
| `entryLogic.js` | Validation, amount calculation, form → API payload |
| `format.js` | Number / date (DD-MM-YYYY) formatting and CSV export |
| `EntryModule.jsx` | Module shell: section sidebar, today's summary, toasts, load / save / delete |
| `EntryForm.jsx` | New-entry form |
| `EntryTable.jsx` | Search, filters, sorting, paging, totals, inline edit, delete confirm |
| `entry.css` | Styles (all classes start with `em-`) |

Backend: `ShoeFactoryApi/Models/MaterialEntry.cs`, `ShoeFactoryApi/Controllers/MaterialEntriesController.cs`, migration `AddMaterialEntries`.

## Data model (`MaterialEntries` table)

| Field | Type | Notes |
|---|---|---|
| `id` | uuid | Generated by the server |
| `date` | date | Required |
| `material` | text | Required, one of `MATERIALS` |
| `quantity` | decimal | Required, > 0 |
| `unit` | text | Required, defaults from the material, editable |
| `articleNo`, `size`, `supplier`, `billNo`, `remarks`, `enteredBy` | text | Optional, stored as null when blank |
| `rate` | decimal | Optional |
| `amount` | decimal | Optional. When a rate is given, the server sets it to quantity × rate |
| `voided` | bool | Soft delete. "Delete" sets it; Undo / Restore clears it |
| `createdAt`, `updatedAt` | timestamp (UTC) | Set by the server |

API (login required): `GET /api/material-entries?includeVoided=true`, `POST`, `PUT /{id}`, `POST /{id}/void`, `POST /{id}/restore`.

## Add or rename a material

Edit the `MATERIALS` array in `materials.js`:

```js
{ name: 'Glue', unit: 'kg', color: '#0f766e' }
```

The form dropdown, filters, totals and badges all pick it up. Renaming does not change entries that were already saved under the old name.

## Swap the storage layer

Every screen gets its data through `createEntryRepository(token)`, which returns `list`, `create`, `update`, `void` and `restore`.
To use a different backend (or localStorage for an offline demo), rewrite those five functions in `entryRepository.js` and keep the same return shapes. No component needs to change.
